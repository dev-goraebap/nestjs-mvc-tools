# 문제 해결 가이드

## 프로젝트 기본 라이브러리 및 주요 고려 사항

이 프로젝트는 템플릿 옵션을 통해 필요한 라이브러리만 선택하여 설치할 수 있습니다. @hotwired 시리즈와 @tailwindcss 라이브러리를 프로젝트 요구사항에 따라 선택적으로 포함할 수 있으며, 기본값은 가장 기본적인 `minimal` 템플릿입니다.

## Vite HMR 지원 이슈

### 문제 상황

현재 프로젝트에서는 Vite의 HMR(Hot Module Replacement)이 제대로 지원되지 않습니다. 이로 인해 코드를 수정해도 웹사이트에 즉시 반영되지 않고, 변경 사항을 확인하려면 수동으로 새로고침해야 합니다.

### 원인 분석

이러한 현상은 Vite가 주로 정적 에셋 관리를 담당하고, Edge.js 템플릿 엔진은 NestJS 서버 측에서 실행되기 때문에 발생합니다. 즉, 프론트엔드와 백엔드 환경이 분리되어 있어 Vite의 HMR 기능을 온전히 활용하기 어렵습니다.

### 기술적 배경

AdonisJS는 ESM(ECMAScript Modules) 환경을 기반으로 설계되어 프론트엔드 구성 자체가 하나의 프로젝트처럼 긴밀하게 작동합니다. 반면 NestJS는 CommonJS 환경에서 널리 사용되어 왔습니다. 

NestJS에서도 ESM 설정이 불가능한 것은 아니지만, 기존 라이브러리와의 충돌 등 예상치 못한 문제가 발생했을 때 대응하기 어렵다고 판단했습니다. 따라서 NestJS의 기존 환경 구성은 건드리지 않고, 확장하는 구조를 택했습니다.

### 현재 상황

이러한 접근 방식 때문에 프론트엔드와 백엔드를 독립적으로 빌드하고 배포하는 것이 일반적이며, HMR 통합에 제약이 발생하고 있습니다.

현재로서는 개발 편의성과 관리 효율성 사이의 적절한 타협점을 찾기 위해 노력하고 있습니다.

### 해결 방법 (임시)

현재로서는 다음과 같은 방법으로 개발 경험을 개선할 수 있습니다:

1. **프론트엔드 변경 시**: Vite 개발 서버를 통해 CSS/JS 변경사항은 바로 반영됩니다
2. **템플릿 변경 시**: NestJS 서버를 재시작하거나 브라우저를 수동으로 새로고침하세요
3. **동시 개발 시**: 두 개의 터미널을 사용하여 각각 모니터링하세요

```bash
# 터미널 1: NestJS 서버
npm run start:dev

# 터미널 2: Vite 개발 서버  
cd resources && npm run dev
```

## 라이브러리 테스트 이슈

### 문제 상황

이 라이브러리는 Edge.js 템플릿 엔진을 사용하는데, 이는 ESM(ECMAScript Modules) 환경에서 사용되도록 만들어졌습니다. 하지만 대부분의 NestJS 프로젝트는 CommonJS 환경에서 실행되기 때문에 테스트 환경 구성에 어려움이 있습니다.

### Jest E2E 테스트의 제약사항

초기에는 `tests/tmp` 디렉토리에서 Jest를 활용한 E2E 테스트를 시도했으나, 다음과 같은 문제들로 인해 포기하게 되었습니다:

#### 주요 문제점

- **모듈 시스템 충돌**: CommonJS 환경의 Jest에서 ESM 라이브러리인 Edge.js를 로드할 때 발생하는 호환성 문제
- **복잡한 설정**: Jest의 ESM 지원을 위한 설정이 복잡하고, 다른 라이브러리들과의 충돌 가능성
- **불안정한 테스트 환경**: 모듈 로딩 순서나 설정에 따라 테스트가 간헐적으로 실패하는 문제

#### 시도했던 해결 방법들

1. **Jest ESM 설정**: `jest.config.js`에서 ESM 지원 활성화
2. **Transform 설정**: Babel 또는 TypeScript 컴파일러 설정 조정
3. **모듈 매핑**: 특정 모듈들에 대한 수동 매핑 설정

하지만 이러한 방법들도 일관성 있는 테스트 환경을 제공하지 못했습니다.

### 대안: 수동 테스트 환경

이러한 제약사항으로 인해 현재는 `tests/manual-test-app`에서 실제 NestJS 애플리케이션을 실행하여 수동으로 기능을 테스트하고 있습니다:

```bash
# 테스트 앱 실행
cd tests/manual-test-app
npm install
npm run start:dev
```

#### 수동 테스트 앱의 구성

```
tests/manual-test-app/
├── src/
│   ├── app.controller.ts    # 기본 기능 테스트
│   ├── app.module.ts        # 모듈 설정 테스트
│   └── exception.filter.ts  # 예외 처리 테스트
├── resources/               # 프론트엔드 리소스
└── package.json
```

#### 테스트 시나리오

1. **기본 렌더링**: Edge.js 템플릿 렌더링 확인
2. **CSRF 보호**: 토큰 생성 및 검증 확인
3. **플래시 메시지**: 메시지 설정 및 표시 확인
4. **에셋 파이프라인**: Vite 빌드 및 제공 확인
5. **예외 처리**: 404, 500 에러 페이지 확인

### 향후 개선 계획

1. **테스트 환경 개선**: ESM 호환성 문제 해결을 위한 별도 테스트 전략 수립
2. **CI/CD 통합**: GitHub Actions를 통한 자동화된 테스트 환경 구축
3. **단위 테스트**: 개별 기능들에 대한 분리된 단위 테스트 작성

## 일반적인 문제 해결

### 1. 세션 관련 경고 메시지

**문제**: 지속적인 세션 관련 경고 메시지 발생

**해결**: [설정 가이드](./CONFIGURATION_KO.md#중요-세션-의존성)를 참고하여 express-session 설정

### 2. 정적 에셋이 로드되지 않음

**문제**: CSS, JS 파일이 404 에러로 로드되지 않음

**해결**: `main.ts`의 `useStaticAssets` 설정과 `NestMvcModule`의 `staticAssetPrefix` 설정이 일치하는지 확인

### 3. CSRF 토큰 검증 실패

**문제**: 폼 제출 시 CSRF 토큰 에러 발생

**해결**: 
- 템플릿에 `{{ csrfToken }}` 변수가 올바르게 설정되었는지 확인
- 폼의 `_csrf` hidden 필드 확인
- Hotwired 사용 시 meta 태그 설정 확인

### 4. 프로덕션 빌드 에러

**문제**: 프로덕션 환경에서 정적 에셋이 제대로 제공되지 않음

**해결**:
```bash
# NestJS와 Vite 모두 빌드해야 함
npm run build  # nest build && cd resources && npm run build
```

### 5. 템플릿 렌더링 에러

**문제**: Edge.js 템플릿 파싱 에러

**해결**:
- 템플릿 문법 확인 (Edge.js 문법 가이드 참조)
- 파일 경로 및 확장자(.edge) 확인
- 변수명 오타 확인
